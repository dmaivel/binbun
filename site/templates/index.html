Provenance

Every line of decompiled C leads back to the instructions it came from, and every inferred type and name comes with its evidence.

Verification

Each function's decompiled form is run beside its machine code from the same states. Differences are reported, not hidden.

Familiar keys

Listing, graph, C and hex views with the shortcuts reverse engineers already know: N, Y, X, G, Space, and the C, U, D, A, * and P corrections.

Collaboration

Share a project and work on it together, end-to-end encrypted: edits, cursors, chat and threads at addresses, each change kept with its author.

Python and agents

The whole engine from Python, headless or in your open window. Agents use it the same way or through binbun mcp, and their edits carry their name, one undo step each.

Open source

MIT or Apache-2.0, written in Rust. Projects live outside your binaries and travel as single files.

Undefined stays undefined.

The same imul by zero in our twin example prints 0xdead on an Intel Raptor Cove P-core and 0xbeef on a Gracemont E-core because a multiply leaves the zero flag undefined: Raptor Cove clears it, Gracemont sets it. binbun keeps that value unknown, as _ZF_undefined in the reading view and binbun_undefined_bool() in the exact view, with the instruction and the reason. It does not turn one processor's answer into a constant for every machine.

Every line has a source.

Hover a line of C to highlight the instructions it came from. Hover a marked name or type, or choose Why…, to see the evidence behind it. The explanation stays tied to the code, so you can check an inference instead of trusting it.

Verify.

Run binbun verify or choose Verify Function in the app to compare the decompiler's structured form with its lifted machine code, interpreted from the same states. Differences are reported, not hidden; a function that cannot be checked is labelled as such. This is sampled verification, not a proof or native execution of compiled C; the verification guide explains the boundary.

The disassemblers, on their own.

binbun's decoders are libraries you can use without the rest: pip install binbun for Python, the binbun-disasm crate (or binbun-x86 and binbun-aarch64, one architecture each) for Rust, and libbinbun for C and C++.

The same example in each language, and the rest of the engine, are in the examples.
